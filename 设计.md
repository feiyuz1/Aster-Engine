# 小型游戏引擎设计文档

**文档版本**：V1.0
**设计目标**：构建一个具备基础运行时、资源管理、ECS、任务系统、渲染管线、脚本扩展能力的小型游戏引擎核心框架。
**面向场景**：

* 学习型引擎
* 面试架构表达
* 小型项目原型验证
* 后续可扩展为编辑器 + Runtime 分层系统

---

# 1. 引言

## 1.1 文档目的

本文档用于描述一个小型游戏引擎的整体架构设计，包括：

* 模块划分
* 模块职责
* 核心对象关系
* 关键系统设计思想
* 类图风格的接口骨架

本文档重点吸收了本次模拟面试中涉及到的知识点，包括：

* ECS 架构
* 资源生命周期管理
* 异步加载
* 内存池与碎片控制
* 多线程任务调度
* 渲染优化
* 场景加载与流式处理
* 脚本热更新
* 平台抽象与模块解耦

---

## 1.2 设计原则

本引擎设计遵循以下原则：

### 1. 模块化

各模块通过清晰接口协作，避免强耦合。

### 2. 分层

平台层、核心层、资源层、场景层、渲染层、脚本层、运行时层职责清晰。

### 3. 面向性能

优先考虑缓存友好、批处理、减少频繁分配、异步化、低锁化设计。

### 4. 可扩展

资源类型、渲染后端、脚本语言、系统模块都可扩展替换。

### 5. 运行时与编辑器解耦

引擎核心应可脱离编辑器独立运行。

# 2. 总体架构设计

---

## 2.1 架构分层

引擎整体分为以下层级：

```text
+--------------------------------------------------+
|                    Editor Layer                  |
+--------------------------------------------------+
|                   Runtime Layer                  |
+--------------------------------------------------+
| Render | Script | Physics | Animation | Audio   |
+--------------------------------------------------+
|             Scene / ECS / Gameplay               |
+--------------------------------------------------+
|           Resource / Asset Management            |
+--------------------------------------------------+
|       Task System / Memory / Event / Core        |
+--------------------------------------------------+
|      Platform Abstraction / File / Time / OS     |
+--------------------------------------------------+
```

---

## 2.2 层级职责说明

### Platform Layer

负责屏蔽操作系统、文件、线程、时间、窗口等平台差异。

### Core Layer

提供日志、事件、对象句柄、断言、配置、基础容器封装等公共能力。

### Memory Layer

提供内存池、线性分配器、分级分配器等高性能内存管理组件。

### Task Layer

提供线程池、Job System、依赖调度、异步执行框架。

### Resource Layer

负责资产加载、资源缓存、引用管理、异步加载、卸载回收。

### Scene / ECS Layer

负责实体、组件、系统组织，以及场景对象生命周期管理。

### Render Layer

负责渲染设备抽象、渲染队列、材质、Shader、剔除、LOD、渲染提交。

### Script Layer

负责脚本虚拟机、绑定接口、脚本实例、热更新机制。

### Runtime Layer

负责主循环与模块驱动。

### Editor Layer

负责可视化编辑，不直接侵入 Runtime 内核。

```cpp
#pragma once
#include <functional>
#include <atomic>
#include <memory>

namespace MiniEngine
{
    enum class JobPriority
    {
        Low,
        Normal,
        High,
        Critical
    };

    class Job
    {
    public:
        std::function<void()> task;
        std::atomic<int> dependencyCount{0};
        JobPriority priority = JobPriority::Normal;
    };

    using JobHandle = std::shared_ptr<Job>;

    class JobQueue
    {
    public:
        void Push(const JobHandle& job);
        JobHandle Pop();
        bool Empty() const;
    };

    class WorkerThread
    {
    public:
        explicit WorkerThread(JobQueue* queue);
        void Start();
        void Stop();
        void RunLoop();

    private:
        JobQueue* m_queue = nullptr;
        std::atomic<bool> m_running{false};
    };

    class JobSystem
    {
    public:
        void Initialize(uint32_t workerCount);
        void Shutdown();

        JobHandle CreateJob(std::function<void()> func, JobPriority priority = JobPriority::Normal);
        void Submit(const JobHandle& job);
        void Wait(const JobHandle& job);

    private:
        JobQueue m_globalQueue;
        std::vector<std::unique_ptr<WorkerThread>> m_workers;
    };
}
```

```text
    -> 主线程 / 渲染线程提交 GPU 资源
    -> ResourceState = Loaded
    -> EventBus 发布资源可用事件
```

# 7. 面向面试的设计亮点总结

这套设计如果你拿去说，面试官通常会比较认可的点有：

### 1. 结构清晰

不是一堆类乱堆，而是分层明确。

### 2. 懂 ECS 的本质

你不是只会说 Entity / Component / System 三个词，而是知道：

* 数据与行为分离
* 缓存友好
* 适合批处理

### 3. 懂资源系统的核心

* 缓存
* 异步加载
* 生命周期管理
* 状态机

### 4. 懂内存优化

* 线性分配器
* 对象池
* 分级分配
* 线程本地池

### 5. 懂并发调度

* Job System
* 依赖关系
* 低锁队列
* 后台加载

### 6. 懂渲染不是只会说“优化”

而是能拆：

* 剔除
* LOD
* 排序
* 批处理
* 渲染路径

### 7. 懂热更新的风险点

* 状态迁移
* 接口隔离
* 一致性检查
* 安全边界
