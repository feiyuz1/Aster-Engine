# 项目 C++ 代码开发（P0）

现在可以让项目自己的 C++ 逻辑在编辑器 Play 和独立游戏中运行。项目编译成 DLL；引擎通过 SDK 提供查找场景对象、读取/修改 Transform、输入和日志服务。

本阶段的代码入口是“整个项目的一次运行会话”。示例查找名为 `Player` 的现有实体，每秒增加 90 度 Y 轴旋转。它还不是能在 Inspector 的“添加组件”中挂载的项目组件。

## 日常创建项目（推荐）

开发机先安装 Visual Studio 2022 的“使用 C++ 的桌面开发”和 CMake 3.21+。完整 SDK 包包含编辑器和项目模板，不需要下载引擎源码。

1. 双击 SDK 根目录的 `TinyEngine.cmd`。
2. 在“新建项目”中填写名称，点击“浏览”选择保存目录。
3. 点击“创建并打开”。编辑器自动生成项目、生成 VS 工程并编译项目 DLL；完成后自动进入项目。
4. 点击“运行”，Player 模型会旋转，也可以在属性面板观察 Y 旋转值；点击“停止”恢复编辑场景。

名称以英文字母开头，可包含英文字母、数字和下划线。保存目录可含中文或空格。受 Visual Studio 路径长度限制，建议使用较短的项目目录，例如 `D:/Games`。

首次编译时窗口仍可响应，不需要输入命令或填写 SDK 路径。编译失败会保留项目，显示错误详情；修复后点击“重新编译”。输出也保存在项目的 `Saved/ProjectBuild.log`。目标目录已存在时不会覆盖。

新项目的代码位于 `Source/Game.cpp`，`build/项目名.sln` 可直接在 VS 中打开。工程提供 `项目名Editor` 和 `项目名Game` 两个启动项，分别打开本项目的编辑器和独立游戏；SDK 包含编辑器时默认选 Editor。修改代码后的流程仍是保存场景、关闭编辑器、在 VS 中重新生成项目、重新打开；当前没有运行中换库。

需要重新生成工程时，先双击 SDK 的 `Programs/ProjectTool/TinyEngineProjectTool.exe` 注册一次右键菜单，之后右键 `.tinyproject` 选择“生成 Visual Studio 工程”。Windows 11 请展开“显示更多选项”。工具只生成工程；编译仍在 VS 中完成。SDK 手动安装时另外安装 `ProjectTool` 组件（建议 Release 构建）。

引擎开发者直接构建 `tinyengine_editor` 时，也会自动在构建目录的 `ProjectSDK` 中准备匹配 SDK；源码版编辑器使用该 SDK 创建项目。下面的命令用于维护 SDK 和手动构建，也可用于定位工具链问题。

## 1. 准备 SDK

要求 Windows x64、Visual Studio 2022 C++ 工具链、CMake 3.21+、C++17。项目和 SDK 必须使用相同的编译器版本及 Debug/Release 配置。

先在引擎目录构建。下面沿用已经配置好的 `Intermediate/Build/Editor`；依赖配置见[构建指南](构建指南.md)。

```powershell
cmake --build Intermediate/Build/Editor --config Debug --target tinyengine_project_sdk tinyengine_game tinyengine_editor
cmake --build Intermediate/Build/Editor --config Release --target tinyengine_project_sdk tinyengine_game
cmake --build Intermediate/Build/Editor --config Release --target tinyengine_project_tool
cmake --install Intermediate/Build/Editor --config Debug --component ProjectSDK --prefix D:/TinySDK
cmake --install Intermediate/Build/Editor --config Release --component ProjectSDK --prefix D:/TinySDK
cmake --install Intermediate/Build/Editor --config Debug --component ProjectRuntime --prefix D:/TinySDK
cmake --install Intermediate/Build/Editor --config Release --component ProjectRuntime --prefix D:/TinySDK
cmake --install Intermediate/Build/Editor --config Debug --component EditorRuntime --prefix D:/TinySDK
cmake --install Intermediate/Build/Editor --config Release --component ProjectTool --prefix D:/TinySDK
```

`ProjectSDK` 包含头文件、小型包装库、CMake 辅助和示例。`ProjectRuntime` 包含按配置存放的游戏宿主及 CMake 找到的可再发行运行库；`EditorRuntime` 单独安装编辑器。Debug 调试仍要求开发机具备对应 VS 调试运行库。Windows 的 OpenGL、音频及系统 DLL 由系统提供。

SDK 可以整体移动。外部项目只依赖安装目录，不需要引擎源码、SDL 或 ImGui 的头文件。

## 2. 创建外部项目并编译

把 `D:/TinySDK/share/tinyengine/templates/ProjectModule` 整个复制到自己的新项目目录，例如 `D:/Games/RotateGame`。模板已包含 `Game.tinyproject`、`Start.scene`、`CMakeLists.txt` 和 `Source/Game.cpp`。

```powershell
cmake -S D:/Games/RotateGame -B D:/Games/RotateGame/build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=D:/TinySDK
cmake --build D:/Games/RotateGame/build --config Debug
```

CMake 中最核心的一行是：

```cmake
find_package(TinyEngine CONFIG REQUIRED)
tinyengine_add_project_module(
    TARGET RotateGame
    PROJECT_ID sdk-consumer
    MODULE_ID game.rotate
    SOURCES Source/Game.cpp)
```

自己的项目应设置独立且长期不变的 `PROJECT_ID` 和 `MODULE_ID`，并同步 `.tinyproject` 中的 `project.id` 和 `code.module`。新增编译单元列入 `SOURCES`，运行时第三方 DLL 列入 `RUNTIME_DEPENDENCIES`；其他非代码构建输入也应显式列明。文件必须位于项目内。辅助会跟踪项目代码、隐式头文件和 CMake 配置，并在目录配置结束时计入目标设置及用户缓存选项。生成目录、运行副本、日志和资源数据不会作为普通源码扫描。系统 DLL 不列入项目依赖。

构建设置应写入 CMake 或其缓存选项；不要直接修改生成的 `.vcxproj` 来保存编译设置。引擎源码或 Git 提交变化也会自动更新 SDK 身份，已有项目需要用匹配的新 SDK 重新编译。

成功编译后会生成 `Binaries/Windows-x64/Project.modules`。Development 对应 Debug，Shipping 对应 Release；两个配置各自保存 SDK 身份和构建产物。不要手改清单来绕过兼容检查。

## 3. 在编辑器和独立游戏中运行

```powershell
& D:/TinySDK/bin/Debug/tinyengine_editor.exe D:/Games/RotateGame/Game.tinyproject
& D:/TinySDK/bin/Debug/tinyengine_game.exe D:/Games/RotateGame/Game.tinyproject --frames=3
```

编辑器打开后，点击 Play，项目的 `OnBeginPlay`、`OnUpdate` 开始执行。示例实体只有 Transform，可在属性面板观察旋转值；使用自己的模型场景时，把目标实体命名为 `Player`。Stop 调用结束和销毁，再恢复运行前的场景。再次 Play 会创建新的会话。

示例日志应包含 `P0_PROJECT_BEGIN`、`P0_PROJECT_ROTATED`、`P0_PROJECT_END`。也可查看项目的 `Logs/TinyEngine.jsonl`。限帧参数只用于快速验证，正常游戏运行时省略。

SDK 的 `Context` 是访问引擎的入口：`FindEntity` 查找实体，`GetTransform/SetTransform` 复制 Transform，`GetAxis/IsDown` 读输入，`Log` 写日志。失败可查 `GetLastResult()`。实体句柄包含世界身份和实体代次；不要在 Stop 或场景替换后继续使用旧句柄。场景服务要求主线程访问，编辑阶段禁止修改场景。

## 4. 用 Visual Studio 断点调试

用 VS 打开外部项目的 `build/TinySDKConsumer.sln`，选择 Debug/x64。配置下拉框中的 Debug/Release 表示编译方式，编辑器或游戏由启动项目决定：

1. 右键 `RotateGameEditor` →“设为启动项目”。
2. 在 `Source/Game.cpp` 的 `OnBeginPlay` 或 `OnUpdate` 中设置断点，按 F5。
3. VS 先编译项目 DLL，再启动编辑器并打开对应 `.tinyproject`。在编辑器点击 Play 后，项目代码开始执行，断点才会触发。
4. 需要调试独立游戏时，把启动项目改为 `RotateGameGame` 再按 F5，游戏会直接执行项目逻辑。

新打开的完整编辑器 SDK 工程默认选 Editor；仅安装项目 SDK 的工程默认选 Game。SDK 必须包含当前 Debug/Release 配置的 `bin/配置/tinyengine_editor.exe` 或 `tinyengine_game.exe`，缺失时启动项的构建会提示需要安装对应运行时。当前项目模块支持 Debug/Release，请勿选择 MinSizeRel 或 RelWithDebInfo。

旧项目更新 SDK 后，右键 `.tinyproject` 重新生成工程即可得到这两个启动项。旧模板只生成 DLL 调试设置也可继续使用；VS 会保留以前的启动选择，因此已打开过的解决方案需要手动“设为启动项目”一次。`ALL_BUILD` 只负责编译，不是可运行程序。

手写项目可向 `tinyengine_add_project_module` 传入 `PROJECT_FILE Game.tinyproject`；未传入时会查找项目根目录唯一的 `.tinyproject`，没有或存在多个文件时不会猜测，需要显式指定。

已经单独打开的编辑器仍可在 VS“附加到进程”中选择 `tinyengine_editor.exe`，以本机代码附加，再点击 Play。调试器暂停时编辑器窗口也会暂停，这是同进程调试的正常行为。

宿主实际加载的是 `Library/ProjectModules/<BuildId>/` 下的 DLL 和匹配 PDB。VS“调试 → 窗口 → 模块”可以核对加载路径、符号状态和源文件。若断点空心，先核对 Debug 配置、当前 BuildId、PDB 和源码版本。

查看引擎调用栈和源码还需要编辑器/游戏宿主自己的 PDB，只有项目 DLL 的 PDB 不够。`EditorRuntime` 和 `ProjectRuntime` 安装组件会把生成的宿主 PDB 放在对应 EXE 旁。两者必须来自同一次链接；VS“模块”窗口中右键 `tinyengine_editor.exe` 或 `tinyengine_game.exe` 可以加载符号、查看符号加载信息。源码使用本机对应版本的引擎文件；PDB 记录的源路径不存在时，按 VS 提示定位源码文件。保留源码匹配检查，避免把不同版本的源码当成当前运行代码。

## 5. 修改代码和处理失败

P0 的流程是：保存场景、关闭编辑器/游戏、重新编译、重新打开。运行期间不提供换库；DLL 虽然使用影子副本加载，修改后仍须重启宿主才能使用新代码。

编译失败时保留旧清单和旧产物。它们仍代表上一次成功构建的代码。修复后再编译，新成功构建会更新清单。不要把“编译失败但旧版本还能运行”误认为新代码已生效。

默认 `code.required=true`。DLL 缺失或身份不匹配时，编辑器可以打开已有场景，但会阻止 Play 并给出错误；独立游戏启动失败。显式指定的项目或启动场景出错时，不会偷偷打开演示场景。
