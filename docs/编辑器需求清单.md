# TinyEngine 编辑器需求清单

- 建立日期：2026-07-20
- 适用版本：TinyEngine 0.27.0 及后续版本
- 范围：当前编辑器尚未提供、需要新增设计和实现的能力

## 1. 文档边界

本文只记录“当前从未实现的新能力”，不记录已有功能执行错误，也不把使用方式不明显直接描述为功能缺失。

- 已有功能结果错误或工程保护失效：进入[编辑器 UI 故障清单](编辑器UI测试与故障清单_2026-07-17.md)，类型为 `Bug`。
- 已有功能可以运行，但交互、反馈或可发现性不足：进入故障清单，类型为 `易用性缺陷`。
- 当前没有相应代码路径，需要新增产品设计、平台适配或内容：进入本文，类型为 `需求`。

需求优先级表示排期价值，不表示当前功能发生故障：P0 为发布必需，P1 为核心工作流必需，P2 为明显改善生产效率，P3 为低风险增强。

## 4. 详细需求

### TE-REQ-001 · P2 · 标准示例场景与基准内容

背景：当前 `Demo.scene` 使用的 `player.mesh` 只有一个三角形，场景放置了两份；GroundCollider 没有可见 Mesh，项目没有天空或 Environment。Sun 方向光实际存在并参与渲染，但用户看到的是黑色背景和两个三角形。

目标：提供打开后即可判断相机、灯光、阴影、材质、网格和基础后处理是否工作的参考场景，而不是把内容缺失误判为渲染故障。

验收标准：

- 场景至少包含主相机、方向光、可见地面、三个可区分的标准几何体和天空/环境。
- 至少覆盖基础 PBR 材质、方向光阴影、透明材质和一个后处理效果。
- 地面 Mesh 与 Collider 的关系清晰，可通过 Inspector 验证。
- 提供固定相机位和中英文截图基线；Release Editor 与打包 Game 的主体内容一致。
- 示例资产使用项目相对路径，并通过 `ValidateAssets`、`ValidateScenes` 和打包启动场景校验。

### TE-REQ-002 · P2 · 系统文件选择器和模型格式过滤

背景：当前模型导入弹窗使用文本框接收源文件路径，手工输入可以完成导入；平台原生选择器、过滤器和最近目录从未实现，因此这是新增需求，不是现有导入器 Bug。

目标：像 Qt `QFileDialog` 一样从本机文件系统选择模型，同时保持 Assimp 支持格式与 UI 过滤列表一致。

验收标准：

- Windows 使用 `IFileOpenDialog`；其他平台通过对应原生接口或统一 Native File Dialog 适配层实现。
- 提供“所有支持模型”、FBX、glTF/GLB、OBJ 和“所有文件”等过滤组。
- 支持格式直接由 `AssimpImporter::GetSupportedExtensions()` 生成，禁止维护第二份易漂移的硬编码列表。
- 记住最近目录；取消选择不改变导入设置，也不产生错误日志。
- 选择后即时校验文件存在、可读、扩展名受支持，并在导入按钮旁显示明确错误。
- 无 Assimp 构建仍能正常编译，且不显示不可用入口。

### TE-REQ-003 · P2 · Assets 图标网格和真实模型缩略图

背景：当前 Assets 主区域只显示“类型 + 完整路径”的纵向文本列表。单击资产后才在下方生成单项预览；Prefab 没有真实模型缩略图。复杂导入会生成大量 Mesh 和 Material，完整 Prefab 很容易被淹没。

目标：提供适合实际项目规模的可视化资产浏览器，使用户能够快速找到完整模型、子网格、材质和纹理。

验收标准：

- 支持 List/Grid 切换和缩略图尺寸调节，并持久化用户选择。
- 显示文件夹层级、面包屑、名称搜索和资产类型过滤；默认隐藏或可选择隐藏 `.meta`。
- Mesh、Prefab、Material 和 Texture 使用可辨识缩略图，其他资产类型使用统一图标。
- Prefab 缩略图按完整层级和材质渲染，不使用通用棋盘格代替。
- 缩略图异步生成、磁盘缓存并按资产内容/依赖哈希失效；滚动资产列表时不能阻塞编辑器主线程。
- 右键“重新生成缩略图”继续可用，并支持多选批量重建。
- 至少用包含 80 个子 Mesh 的复杂模型验证搜索、过滤、滚动和缩略图缓存。

### TE-REQ-004 · P2 · 非网格实体图标、可视化和点选

背景：当前 Scene View Picking 只处理 Mesh 和 Collider Bounds。Camera、Directional/Point/Spot Light、Audio Source 等没有可见网格的实体无法从画面点选。由于从未提供编辑器图标，这部分属于需求；Mesh/Collider 已有 Picking 的错误仍由 TE-QA-017 跟踪。

目标：让非网格实体在编辑状态下可见、可点选、可区分，同时不影响 Game 渲染。

验收标准：

- 为 Camera、三类 Light、Audio Source 和常用逻辑实体提供编辑器专用图标。
- 显示 Camera Frustum、Light Direction/Range/Cone 和 Audio Range 等可开关辅助线。
- 图标具有稳定屏幕尺寸，并进入无 TAA Jitter 的 Entity ID Picking Pass。
- 图标、真实网格和 Gizmo 重叠时有明确优先级，并支持重叠命中循环选择。
- 辅助图标只在 Editor 构建和编辑状态出现，不进入发布包的运行时画面与 Draw Call 统计。
- 增加坐标到 Entity ID 的确定性自动测试，覆盖 DPI 缩放和窗口尺寸变化。

## 5. 与现有易用性缺陷的关系

TE-QA-023 仍是易用性缺陷：Prefab 拖放和双击实例化已经实现，但没有“放入场景”菜单、拖拽提示和导入完成引导。修复它不依赖 TE-REQ-003 全部完成，可以先增加右键动作、完成通知和明确的拖动预览。

需求实现后必须同步使用指南、项目架构、实现日志和自动测试；满足全部验收标准并取得可重复证据后，状态才能改为“已完成”。
