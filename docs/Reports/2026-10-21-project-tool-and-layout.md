# ProjectTool 与仓库整理验收

本次顺序：先提交独立项目工具，再提交 Programs、Scripts 与文档迁移，最后提交构建目录与本地归档入口。

## 已验证的代码

- 独立 ProjectTool：Release 2/2 测试通过，不链接引擎；导入表只有 Windows 系统 DLL。
- 工程生成：中文和空格路径、SDK A→B 缓存更新、无效参数、CMake 启动失败与日志路径。
- 菜单：临时 HKCU 根下验证注册、重复注册、更新、引用路径、所有者保护、注销和外部菜单保护。构建与自动测试不注册真实用户菜单。
- 完整 Debug 回归：34/34，通过用时 371.70 秒，包括编辑器创建项目、项目 DLL 会话、安装 SDK 的 Debug/Release 实际运行、材质、场景保存、撤销、资产维护和编辑器交互。
- 整理后的命令行工具：校验 21 项资源、1 个场景，打包目标和独立程序三帧运行通过。
- 归档保护：错误根目录、目标冲突、外部 CMake HOME、依赖引用、活动进程、路径越界以及移动/回退中断恢复均覆盖。Windows PowerShell 5 和 PowerShell 7 均通过。

代码审查发现的两个归档问题都先由测试复现，再修复：活动的非引擎进程未被识别；文件已移动但状态尚未落盘时无法回退。清单现采用原子替换、前一版本备份和源/目标状态检查。

首次在新目录回归还发现旧测试依赖之前手动构建的 Release 宿主，现由运行时消费测试准备所需配置。Programs 下的测试目录也加入根 CTest 的遍历。

## 本机安装和迁移记录

ProjectTool 已安装到 SDK 的 `Programs/ProjectTool`，当前用户菜单已注册，已通过注册位置的程序实际生成 `.sln`。资源管理器菜单的视觉显示未手动核对；Windows 11 使用经典“显示更多选项”入口。

注册写入失败采用保存旧值并恢复的实现；现有注册表测试未注入写入中途失败。

本机移动以 `Saved/RepositoryMaintenance/*.json` 为准。清单记录实际源路径、目标路径及状态，支持 `-RollbackManifest`。仍被进程或其他构建引用的目录会保留。归档缓存是历史备份；新的可用构建入口是 `Intermediate/Build`。

可执行代码在 `Programs`，共享实现仍在 `src/include`。游戏项目的目录和构建输出约定保持不变。
