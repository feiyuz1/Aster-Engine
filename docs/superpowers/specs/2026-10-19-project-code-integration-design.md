# TinyEngine 项目 C++ 与编辑器一体化设计

日期：2026-10-19。状态：会话中的方案和范围已获用户确认；本文待书面审阅，尚未进入产品实现。

## 1. 开发者最终怎样使用

开发者安装 TinyEngine SDK，在引擎源码目录之外创建 MyGame 项目。游戏代码放在 MyGame 中，使用 C++17 编写，通过公开 SDK 使用实体、输入和资源等能力。

以旋转方块为贯穿示例：

1. 在 MyGame 中编写 RotateComponent，并登记它的旋转速度、目标对象和配置资源参数。
2. 编译项目，打开 TinyEngine 编辑器；“添加组件”中出现“自动旋转”。增加这个类型不修改引擎固定类型清单。
3. 把组件挂到方块上，把速度设为 90，选择目标对象和一份 RotationProfile 配置；可以撤销、重做、复制、保存场景和创建 Prefab。
4. 点击现有 Play，项目的 C++ 逻辑实际执行。暂停时可以检查状态，在 Visual Studio 中可以命中项目代码断点。
5. Stop 恢复 Play 前的编辑场景，测试期间创建的实体、临时参数和游戏会话被清理；再次 Play 从相同创作数据开始。
6. 修改 C++ 后重新编译，重启编辑器使用新代码。正常重启流程保存恢复未落盘的编辑文档，不要求运行中换代码。
7. 打包会构建目标项目代码、处理资源并收集依赖。发布目录脱离开发机的源码和资源目录后可以独立运行，使用相同的项目类型和游戏规则。

“旋转方块”是验证整条链路的例子；同一机制用于门、敌人、技能、角色控制和游戏配置。完成 DLL 装载或只完成示例逻辑不等于完成本设计。

## 2. 已确定的范围和边界

用户已确认按此前推荐方案推进，具体落为以下约束：

| 项目 | 第一版决定 |
|---|---|
| 平台 | Windows x64、Visual Studio 2022 工具链、C++17；其他平台单独扩展 |
| 项目隔离 | 项目消费安装后的 SDK；正常项目构建不读取或编译引擎源码 |
| 代码载体 | 项目 GameRuntime DLL；编辑器和独立游戏启动器共用项目模块宿主 |
| 接口 | 范围受控的版本化 C 接口，外层提供方便项目使用的 C++ SDK |
| 类型发现 | 项目显式登记；首版手写，不依赖 C++ 扫描或代码生成工具 |
| 可扩展内容 | 项目组件、游戏会话逻辑、可反射的数据配置资源 |
| PIE | 扩展现有 Play/Stop；保留单活动 World 和编辑态快照恢复 |
| 修改代码 | 重新编译后重启编辑器；第一版不在活跃进程内替换项目 DLL |
| 编辑状态 | Stop 恢复 Play 前场景；正常代码重启恢复编辑文档，重启后的撤销历史清空并提示 |
| 发布 | 项目 DLL、目标游戏启动器、Cook 资源、资产索引和运行依赖一起发布 |
| SDK 兼容 | 第一版严格绑定 SDK 契约版本和构建标识，不承诺任意编译器或 SDK 版本间兼容 |

独立后续能力：不退出编辑器换库、保留运行状态的热重载、Prefab 变体与嵌套及自动传播、自定义编辑器面板、任意源格式导入器、自定义底层渲染接口、托管脚本和进程外 PIE。这些能力不作为第一版验收前提。

## 4. 方案选择

| 方案 | 适用性 | 本期决定 |
|---|---|---|
| 项目 DLL + C 契约 + C++ 包装 | 可以使用通用编辑器；对象归属明确；符合现有插件边界 | 采用，先只开放实际需要的服务 |
| 项目 DLL 直接使用引擎 C++ ABI + 共享运行时 | 初期接口直观，需要统一对象布局、CRT、工具链与编译选项 | 不作为本期公开项目契约 |
| 静态链接项目专用编辑器 | 生命周期简单，可以使用预编译 SDK，但每个项目要重新链接编辑器 | 不作为常规项目工作流；静态模块适配后续可复用同一注册协议 |
| 进程外运行项目代码 | 隔离崩溃和重启，需要额外编辑通信和显示协议 | 后续能力 |

源码分离由 SDK 消费方式保证，不由 DLL 本身保证。DLL 装载也不自动提供类型登记、保存、调试和发布能力。

## 5. 模块职责和依赖

| 模块 | 职责与公开输入/输出 | 所有权 |
|---|---|---|
| ProjectSDK | C 契约、C++ 包装、登记辅助、句柄和值类型 | 包装对象不拥有引擎；通过契约管理模块对象和资源句柄 |
| ProjectModuleHost | 装载、构建信息检查、注册事务、代码状态、会话调用和关闭 | Engine/工具宿主持有；模块卸载前清理其全部使用者 |
| TypeRegistry | 类型/属性描述、操作表、模块归属和 Schema 迁移 | 宿主持有元数据副本；不依赖项目静态单例 |
| DocumentCodec | 创作数据的编码、旧格式读取、验证、迁移、引用遍历 | 宿主拥有数据记录，可在缺少模块时工作 |
| ExtensionComponentStorage | 按实体和稳定 TypeId 管理项目实例 | 宿主管理记录，模块回调构造/访问/析构真实对象 |
| ProjectBuildService | 配置、构建、输出捕获、成功产物验证和重启请求 | 独立于 ImGui 的服务；后台进程只构建，不替换当前模块 |
| Editor | 属性/资源界面、文档、撤销、Play 操作与构建反馈 | 编辑器文档不交给项目代码持有 |
| GameRuntime | 项目组件、配置资源、玩法和每次运行的游戏会话 | 项目 DLL 持有自身实现；不依赖编辑器或引擎私有头文件 |

依赖方向：编辑器/游戏启动器/无头工具 -> 模块宿主和运行时；项目代码 -> ProjectSDK；SDK 通过 C 契约调用宿主。运行时不链接具体项目。

tinyengine 可以继续静态链接到编辑器、启动器和离线工具。项目 DLL 不链接完整 tinyengine，也不包含第二份引擎全局状态。ProjectSDK 包装库不依赖 SDL、ImGui 或渲染器私有类型。

## 6. SDK、项目清单和构建产物

SDK 安装包包含公开的 ProjectSDK 头文件和包装库、TinyEngineConfig.cmake、版本清单、模板资源、编辑器、游戏启动器及校验/Cook/打包工具。使用 find_package(TinyEngine CONFIG REQUIRED) 和 TinyEngine::ProjectSDK 构建模块；包路径可以包含中文和空格。

SDK 构建标识同时覆盖公开契约版本、引擎修订、平台和工具链。第一版提供 Development 和 Shipping 两套匹配的宿主产物；Development 对应可原生调试的配置，Shipping 对应发布配置。项目代码的 Development 构建生成调试符号并保留正常逐行调试能力。现有引擎 Debug/Release 构建继续有效。

新项目目录包含 Source、assets、CMakeLists.txt、CMakePresets.json、.tinyproject，以及生成的 Binaries、build、Library、Saved 和 Dist。旧项目迁移可以保留原 src 目录。新增 C++ 源文件由规范构建入口发现，不维护手改的 VS 文件清单。

项目文件新增 code.module（稳定模块 ID）、code.required 和 code.manifest（相对模块清单路径）。没有 code 配置表示旧的无代码工作流；配置了模块时 required 默认为 true。不得把引擎源码路径作为 SDK 项目构建的隐式备用路径。

模块清单固定包含模块 ID、ProjectId、接口版本、SDK 构建标识、平台，以及 Development/Shipping 各自的 DLL 路径、PDB 路径、项目 BuildId、来源指纹、Schema 摘要和显式运行依赖。所有项目产物路径相对项目根解析。

构建成功后生成清单，不能在链接失败或产物验证失败时把新构建标记为可用。来源指纹覆盖项目源码、登记代码、构建配置、SDK 标识及显式项目依赖；排除 build、Library、Saved 和 Dist 等生成目录。

编辑器启动时将验证后的 Development 模块和依赖复制到 Library/ProjectModules/<BuildId>/，再加载该副本。构建输出与已加载副本分离，允许编辑器保持打开时编译；采用 SDK 指定的模块依赖查找目录，不依赖当前工作目录。

旧 Game.cpp 项目提供明确迁移流程和备份：原玩法迁入项目会话，main.cpp 入口由 SDK 启动器接替，原 CMake 改为 SDK 消费。未迁移项目不宣称其 EXE 代码已接入 PIE。

## 7. C 契约和 C++ 使用方式

使用独立项目入口 TinyProject_GetAPI，不改变通用 TinyPlugin_GetAPI v1 的既有语义。共享底层平台库句柄/符号查询实现；通用插件 Tick 不代替项目会话。

函数表包括 abi_version、struct_size 和明确调用约定，接口返回状态码和诊断。跨边界仅传递定宽标量、已定义布局的值、UTF-8 指针加长度、句柄以及 C 函数/用户上下文对。不暴露 World、Engine、std::string、std::function、STL 容器或 C++ 虚接口。

首版 Host 能力覆盖日志、内存、实体创建/销毁/有效性、Transform 读写、组件查询和属性访问、输入动作/轴、资源句柄及帧末命令。资源查询必须能报告尚未就绪和失败。所有改变 World 的操作默认主线程执行；需要结构修改的遍历回调排队到安全点提交。

Host 函数表由宿主持久保存，到模块完成关闭后失效。现有 PluginManager 中 Startup 接收局部 HostAPI 的模式不得复制到 ProjectSDK；如果同时修正通用接口，需保留既有行为和回归验证。

字符串输入只保证调用期间有效，需要保留时复制；元数据由注册表深拷贝。跨边界输出使用调用方缓冲区或匹配的显式释放入口。模块创建的 C++ 对象由模块析构；对齐分配和释放保持配对。回调捕获异常并转换为诊断，不能让异常穿过 C 入口；访问冲突不承诺在同一进程内恢复。

C++ 包装提供 Entity、AssetRef<T>、组件登记和安全的字段访问。项目自己的普通类无需登记；只有要由引擎创建、保存、编辑或调度的类型才登记。成员指针和模板实例化留在项目模块内部，由包装生成 C 操作表。

第一版不开放任意引擎私有对象或底层 OpenGL 访问；新增公开能力仍通过相同契约扩展。保留字段语义，新增尾部字段须检查大小，破坏性修改提升 ABI 版本。

## 8. 类型注册、存储和属性

类型拥有稳定的字符串 TypeId，例如 game.rotate；属性拥有稳定 PropertyId，例如 angular_speed。ID 使用模块命名空间、区分大小写、在改 C++ 名称或显示文案时保持不变。内置类型使用 engine 命名空间。RTTI、地址、注册顺序和 DLL 代次不作为持久 ID。

TypeDescriptor 包含 TypeId、显示名、类型种类、Schema 版本、所属模块/代次、属性和操作表。PropertyDescriptor 包含 PropertyId、显示名、值类型、默认值、Editable/Serializable/RuntimeVisible/ReadOnly/Transient 标志，以及可选范围和资源类型约束。

首版组件每个实体每种类型只允许一个实例。行为组件可登记 BeginPlay、Update、FixedUpdate、LateUpdate、EndPlay 回调；纯数据组件不要求回调。项目游戏会话处理全局规则；不要求组件继承引擎虚基类。

注册分为收集、验证、提交。验证重复 ID、必需操作、字段值、默认值、枚举符号、资源类型约束和迁移版本；同一次项目注册失败整体回滚。注册不能依赖活动场景、窗口或 GPU，不能开始玩法。

首版值种类：Bool、Int32、UInt32、Float、Vec3、String、Enum、EntityRef、AssetRef。Float/Vec3 保存足够精度并拒绝非有限值；Enum 保存稳定符号而非 Inspector 列表下标。暂不要求通用数组、嵌套结构或任意二进制对象反射。

ExtensionComponentStorage 按 TypeId 管理实例，记录模块代次并调用构造/析构/get/set 操作。宿主不解释模块对象的内存布局。SDK 获取项目类型实例必须检查类型和代次，借用地址不得跨 World 替换、组件删除或模块关闭保存。

内置类型通过适配器进入同一 TypeRegistry/DocumentCodec；当前内置类型化 ECS 访问保留。完整内置持久字段必须登记，即使不在 Inspector 显示；不能把当前反射表的可见字段直接当作完整存档字段。内置专有字段的转换集中于适配器，不在场景、Prefab、撤销中重复维护类型清单。

## 9. 数据文档、场景和迁移

宿主拥有 WorldDocument，其中包含稳定 ObjectId、父子关系、组件记录和类型化属性。ComponentRecord 包含 TypeId、SchemaVersion、属性和未知数据。DocumentCodec 不需要访问模块对象即可解析、保存和遍历引用。

新写入格式为 TINYSCENE 12，Prefab 使用相同文档编码。实体使用固定生成的 ObjectId，不再用当前槽位排序决定持久身份。文本记录使用 entity/component/property 和明确结束标记；字符串及属性载荷采用 std::quoted 规则。属性记录独立携带 PropertyId、值种类标记和载荷，因此缺少类型时仍可保存和重映射已知引用。

示例形态如下，示例中的 ObjectId 为便于阅读的代称，真实文件使用生成的固定 ID：

```text
TINYSCENE 12
entity "object-a" ""
component "game.rotate" 1
property "angular_speed" Float "90"
property "target" EntityRef "object-b"
endcomponent
endentity
```

未知 TypeId、PropertyId、值种类标记和载荷均保留；保存规范化顺序不要求保留原始空白排版。未知载荷在识别其种类前不得当作 C++ 内存。对象/字段 ID、重复记录、父子环、必需引用和载荷语法须校验。

读取 TINYSCENE 1–11 时先转换为 WorldDocument，并为原有场景内编号生成对应 ObjectId；所有内部引用同批转换。读取不自动改写磁盘，用户明确保存时写新格式。新格式通过当前 BuildCompatibility 场景版本契约同步识别。

默认保存所有 Serializable 字段。新增字段使用登记默认值；已有值不因构造默认值变化而覆盖。改显示名不改 ID；改字段 ID 提供别名转换；改变类型/单位需要按 Schema 版本迁移。迁移在宿主数据上执行，不获取活动 World；失败保留原文档及诊断，原文件不覆盖。

缺少类型或代码 Schema 比文件旧时，在编辑器以 Missing Component/Resource 保留数据，可进行不依赖该类型的编辑并再次保存。不能静默删除或用旧默认值覆盖新数据。必需玩法类型无法物化时阻止 Play、Cook 和发布。

反序列化顺序：解析一次宿主文档 -> 校验和迁移 -> 构建候选实体/组件及引用 -> 成功后替换世界内容。失败销毁候选，保留当前世界和编辑文档。候选构造只设置数据，不调用 BeginPlay。World 内容替换保留宿主服务、监听器和内置系统对象，并统一通知 Engine 清理缓存/旧句柄。

运行时 Entity 保留现有代际校验；SDK 句柄额外关联 World/会话代次，撤销、加载和 Stop 后的旧句柄不可误访问新对象。持久 EntityRef 保存 ObjectId；AssetRef 保存 GUID 与资源类型 ID，路径只用于展示和旧数据修复。

## 10. 编辑操作、引用和 Prefab

Inspector 通过统一读写协议处理内置和项目属性。设置值先验证类型、范围和资源约束，再记录撤销、写入和标脏；无实际变化不产生撤销记录。多选、重置默认值、拖动合并和资源选择继续遵循现有编辑体验。

编辑态 setter 只更新数据，不执行外部副作用。多选或批量操作先验证全部目标和候选值；应用失败恢复本次操作前的数据，不提交撤销记录或脏状态。资源文档与场景文档遵循同一事务规则。

首版保留每文档完整创作数据快照的撤销/重做，包括未知字段和 Missing Component。运行态检查不写入编辑态撤销栈。增加、移除组件及复制对象也经过相同文档事务。

复制/Prefab 创建先构建全部新 ObjectId 映射，再恢复组件和内部引用。同场景复制保留指向集合外的合法场景引用。保存 Prefab 时，指向模板外场景对象的非空引用应拒绝保存并定位字段，避免生成不可独立实例化的资产；用户清除该引用后重试。资源 GUID 保持不变。

缺失类型中带已知 EntityRef 标记的字段仍参与重映射。未知值种类不允许隐含必须重映射的实体引用；无法证明可安全复制时阻止该复制并保留原数据，不生成错误引用。

Prefab 第一版为可重复实例化的模板，不自动向现有实例传播修改。Prefab 源文档保留稳定局部 ObjectId，为后续 source GUID + local ObjectId + 属性路径的 Override 做准备；本期不实现关联 Override、变体和嵌套展开。

资产重命名/移动利用 GUID 保持引用，通用依赖遍历同时服务 AssetRegistry、资产引用窗口、删除检查和 Cook。旧路径引用在能够唯一解析时转换为 GUID，无法解析时保留路径并给出定位信息，发布前必须解决。

## 11. 模块、编辑态和运行态生命周期

模块状态为未配置、缺失、不兼容、已注册、运行中、停止中、已关闭。代码失败与单个数据资源失败分别诊断。注册完成后才扫描/加载项目数据资源及场景，避免资源类型尚未登记就按 Binary 或内置格式处理。

一次宿主初始化：基础服务 -> 检查并装载项目模块 -> 原子登记类型 -> 初始化资产索引和资源服务 -> 加载编辑场景。无头工具使用同一注册路径，仅提供 CPU/文件相关能力，不创建窗口、游戏会话或 GL 对象。

编辑态可创建组件数据实例，但构造、默认值和数据迁移不得启动音频、任务、计时器或玩法。每次 Play 创建新的项目会话，不能直接复用只在 Engine 初始化时创建并缓存实体的旧 GameInstance。

进入 Play：验证必需代码和数据 -> 生成完整编辑快照 -> 建立运行状态和引用 -> 创建项目会话 -> 调用项目/行为 BeginPlay -> 开始帧更新。失败时对已成功开始的部分反序结束并清理，恢复编辑态，不显示成功进入 Play。

普通帧保留现有内置系统相对顺序：输入/UI -> Gameplay -> Script -> 通用插件 -> 项目 Update -> World 系统/VFX -> 固定步循环（项目 FixedUpdate -> Physics）-> Audio -> 项目 LateUpdate -> 渲染/诊断。一个模块的行为回调按照稳定 TypeId/ObjectId 顺序调度。现有 legacy GameInstance 只在未启用项目会话时更新，不能重复执行同一份项目逻辑。

回调中的结构修改在安全点提交；当帧新建行为下一更新周期开始调用。删除请求使对象不再收到后续普通更新，EndPlay/析构各执行一次。所有开始失败、正常 Stop 和宿主退出路径共用成对清理规则。

Stop：停止新项目更新 -> 对已开始行为/会话执行 EndPlay -> 取消/清理项目计时器与事件及运行资源 -> 销毁会话和运行对象 -> 恢复编辑快照 -> 清空累加时间和过期选择/句柄。运行中数据默认不回写场景、配置资源或 Prefab。

宿主退出时，先关闭运行会话，等待使用项目回调的任务完成，销毁项目组件、资源和所有带模块析构逻辑的对象，移除工厂和回调，再注销类型和卸载模块；引擎服务在项目清理需要它们时仍有效。当前 Engine 中较早 UnloadAll 的顺序不得直接用于项目对象。

## 12. 暂停、单步和 Visual Studio 调试

Play 状态区增加 Pause/Resume 和单步操作。暂停停止项目更新、物理、Gameplay 游戏计时器等模拟时间，继续 UI、输入采集、渲染和诊断。恢复时不补跑暂停期间的墙上时钟时间。

单步只在暂停且运行会话有效时启用，以 project.fixedStep 推进一个完整模拟步：对应的普通更新、一个固定更新/物理步和 LateUpdate，然后保持暂停。单步不制造额外累计时间，不影响后续恢复。运行时 Inspector 首版只读显示 RuntimeVisible 属性和错误状态。

项目 VS 配置启动 SDK 编辑器并传入绝对 .tinyproject 路径，工作目录为项目根；也支持手工附加已有编辑器进程。日志和界面显示宿主 PID、实际 DLL/PDB 路径、SDK 标识及项目 BuildId。

Development DLL 和匹配 PDB 成对保存；影子副本保留对应符号。项目入口、BeginPlay、Update、FixedUpdate 和析构都可设断点。原生断点暂停整个被调试进程是正常行为，不当成引擎 Pause；无需为首版编写独立 C++ 调试器。

## 13. 构建、代码更新和文档恢复

ProjectBuildService 复用 VS 工程生成中的进程调用/输出捕获基础，统一 CMake preset 和命令行构建入口。界面显示当前加载 BuildId、源码是否变化、构建中、成功待重启或失败，不把“生成解决方案”当作“构建项目”。

构建期间当前代码继续有效，绝不自动卸载；Play 中成功构建只标记待重启。失败保留旧产物和清单，显式标注当前运行旧代码。若源码已变化而当前代码过期，点击 Play 提示构建或明确选择上次成功版本，不默默使用旧代码。发布必须重新验证目标构建，不使用这个开发期备用选择。

成功后的“重启并使用新代码”流程先要求结束 Play。将全部打开场景文档、未命名场景、当前标签和脏状态写入 Saved/EditorSession；其他有独立编辑文档的材质/图等窗口也先完成安全保存或通过既有未保存处理流程解决。写入恢复数据失败时不退出。

关闭旧宿主后启动 SDK 的同一编辑器并传入项目及本次恢复标识。新进程验证模块，再迁移并恢复文档；未保存场景保持脏状态，不自动覆盖源资产。恢复失败保留原恢复文件供重试。正常重启清空撤销历史并在重启操作说明中提示。

无需重启的资源/参数编辑继续即时生效，只有 C++ 构建更新要求这条流程。第一版没有进程内项目换库按钮，也不把已有 ScriptEngine::ReloadScript 视为原生 DLL 热重载。

## 14. 项目数据配置资源

DataAsset 是项目登记的可反射配置类型，例如 RotationProfile、武器参数或技能配置。通用资产扩展名为 .tdata，格式头为 TINYDATA 1，保存单个 TypeId、SchemaVersion 和与场景相同的属性记录。资产 GUID 沿用 .meta，不在每次保存时更换。

编辑器可以按登记类型创建默认资产，在通用资源 Inspector 中编辑、验证、撤销/重做和原子保存；组件字段可选择匹配类型的 AssetRef。缺少类型时仍保留资产内容并显示诊断。

运行时通过资源句柄读取同一类型数据，缓存由 ResourceManager 管理；项目对象由登记的回调析构。共享配置默认只读，临时玩法状态由组件/会话保存，不覆盖资源文件。

共享 .tdata 第一版不允许保存指向某个场景对象的非空 EntityRef；通用编辑器和发布校验均定位拒绝。它可以使用 AssetRef 引用其他配置或内置资源，依赖遍历对循环使用访问集合防止递归不终止；实际物化的资源依赖环必须报告并拒绝加载。

通用资源类型识别、加载、依赖收集、引用维护和 Cook 消费同一登记描述。自定义加载器注册必须接到实际资源请求入口，不能只保存一个未被调用的注册列表。

首版 .tdata 的 Cook 为类型/Schema/引用校验和规范化输出，运行时读取规范化的数据记录，不要求立刻新增二进制资源格式。项目组件可引用现有模型、材质、纹理、音频等内置资源；首版不把这些资源的底层实现暴露给项目。

## 15. 构建、Cook 与发布

编辑器打包和 package_tool 使用同一个任务编排入口：

1. 固定本次发布使用的项目文件、目标、源指纹和 SDK；检查所有编辑文档的未保存内容，解决后才开始。
2. 构建 Shipping 项目模块，验证 ProjectId、SDK、平台、来源指纹、模块依赖和可用于发布的 Schema。失败立即停止。
3. 选择同一目标 SDK 的游戏启动器；使用目标构建信息校验，不要求编辑器 Development 配置与 Shipping 相同。
4. 在无头工具进程中注册项目类型，校验发布场景、Prefab 和 .tdata，枚举资源依赖并处理旧引用。
5. 第一版包含项目全部运行资产，排除已明确的创作源文件和编辑器缓存；动态拼接名称加载的资源以显式包含清单补充，禁止引用项目外的开发机绝对路径。
6. 使用统一 AssetCooker/PlatformAssetCompiler 处理资源，生成运行时资产索引和 TPAK。所有 AssetRef 可由索引解析为包内逻辑路径；不依赖发布时被排除的 .meta。
7. 收集游戏启动器、项目模块、显式第三方 DLL、非系统传递依赖以及目标所需可再发行运行库，遵循其部署和许可要求。操作系统组件通过目标系统解析；其他缺失依赖导致失败。PDB 可归档为符号产物，不是启动必需文件。
8. 输出 Package.manifest，记录引擎/项目 BuildId、SDK、目标配置、来源指纹、Schema 摘要、依赖、资源清单及哈希。
9. 在全新暂存目录、无关工作目录和不含开发机引擎路径的环境中限帧启动，验证启动场景、项目逻辑标记和资源解析。
10. 全部成功后替换正式发布目录；失败保留上一份可用包并输出定位错误。

Cook 缓存标识覆盖源内容哈希、依赖结果、导入设置、平台、格式版本和相关处理器/模块版本。先保守失效，再考虑更细粒度优化。不能只按时间戳/大小跳过项目类型或处理器变化。

SDK 游戏启动器和 PIE 共用 ProjectModuleHost、TypeRegistry、DocumentCodec 与游戏会话入口。两种宿主允许显示和输入捕获方式不同；同一创作数据、游戏代码来源与模拟参数应产生一致的示例逻辑结果。

## 16. 分阶段实施边界

本规格保存全流程契约。实施计划按依赖顺序拆为下表阶段，每阶段有独立改动和验收；后续阶段不能使已完成阶段的数据/接口契约失效。P0–P4 全部通过才算第一版完成。

| 阶段 | 范围 | 阶段验收 |
|---|---|---|
| P0 SDK 与模块基础 | SDK 安装消费、项目清单、模块入口/检查、最小 Host 服务和会话骨架 | 引擎源码目录外仅用 SDK 编译模块；宿主调用项目回调；不兼容/缺失模块有定位错误；通用插件不回归 |
| P1 类型和数据 | 注册事务、扩展存储、内置适配、WorldDocument、旧格式读取、Missing 保留、Schema 迁移 | 任意新增登记组件不改引擎清单；新旧场景读写；未知类型/字段不丢；失败不替换当前文档 |
| P2 编辑完整性和资源 | 通用 Inspector、属性事务、撤销、复制/Prefab、通用 .tdata、GUID 引用维护 | 编辑/保存/重开/撤销/复制/Prefab 均完整保留项目类型、值和引用；资源移动不破坏引用 |
| P3 PIE 调试与代码迭代 | 项目会话、回调调度和清理、暂停/单步、VS、后台构建、重启恢复 | 项目逻辑实际执行；断点命中；重复 Play 无残留；改代码后使用新 BuildId；失败保留编辑内容 |
| P4 发布闭环 | 目标项目构建、无头登记/Cook、资产索引、依赖收集、暂存提交和独立运行 | 发布包在无开发源码/散装资产依赖的环境运行；自定义类型/资源和 PIE 结果一致；失败不破坏旧包 |

P0 的最小 Host 服务优先实体/Transform/输入/日志和注册所需能力；P1/P2 扩展数据和资源访问。这个交付顺序不意味着首版只支持最小演示功能。

后续另立规格：先做停止 Play 后的进程内换库和失败回滚；再研究运行中状态快照、对象重新实例化、物理/音频/异步状态恢复与更细的热重载支持矩阵。不能以“替换 DLL 成功”宣称运行态热重载完成。

## 17. 第一版整体验收

验证项目位于引擎源码目录之外，安装 SDK 后隐藏源码目录仍能配置和构建。测试资源含两个相互引用的场景对象、项目 RotateComponent、RotationProfile.tdata、内置模型/材质，以及一个带项目组件的 Prefab。

| 编号 | 操作 | 必须观察到的结果 |
|---|---|---|
| A01 | 仅修改项目，登记第二个新组件并构建、重开 | 编辑器组件菜单出现新类型，未修改引擎清单 |
| A02 | 修改各基础字段、资源和对象引用，保存重开 | 类型和值完整，引用解析正确 |
| A03 | 多选、重置默认值、连续拖动、移除组件、撤销重做 | 事务数量与内容正确，其他字段不变 |
| A04 | 同时复制两个内部互引对象，保存/实例化 Prefab | 副本内部引用指向副本；资源 GUID 保持；Prefab 外部场景引用被定位拒绝 |
| A05 | 临时移走项目模块，打开并修改场景、保存，再恢复模块 | Missing 状态下数据保留；恢复后组件及原值出现；缺失期间 Play/发布明确失败 |
| A06 | 增加字段、改变显示名、字段 ID 别名、改变单位/类型、加载更高 Schema | 默认值/迁移规则生效；不可迁移记录保留，原文档不被覆盖 |
| A07 | 在迁移、属性 setter、候选构造和注册中注入失败 | 没有半注册类型或半替换 World；当前编辑数据可继续使用 |
| A08 | Play 修改实体、创建对象和计时器，再 Stop，连续重复 | 恢复原编辑场景，所有运行会话成对创建/销毁，无重复回调或残留句柄 |
| A09 | 暂停等待、连续单步、恢复 | 暂停无模拟推进；每次单步一次；恢复不补算等待时间 |
| A10 | VS 启动编辑器或附加，命中项目 Begin/Update/Fixed/End 断点 | 使用正确 DLL/PDB，可查看项目 C++ 值及调用栈 |
| A11 | 有未保存场景时构建并重启；再制造编译失败/恢复失败 | 成功使用新 BuildId 并恢复脏文档；失败保留旧会话/恢复数据并报告，不隐瞒旧代码 |
| A12 | 修改项目资源、移动引用资源、改变 Schema/处理器再增量 Cook | 引用保持，相关缓存失效，Cook 和运行索引一致 |
| A13 | 打包并从无关工作目录独立启动 | 加载 Shipping 项目模块，旋转/输入等逻辑和配置与 PIE 一致，不访问开发源码或散装资产 |
| A14 | 使用旧 DLL、缺失第三方依赖、失效引用或项目外绝对资源路径打包 | 构建/校验/收集相应阶段失败，原发布包可用 |
| A15 | 现有 Demo、无代码项目、旧场景、材质/导入、资产引用/删除与通用插件回归 | 原工作流可用；不为接入项目代码破坏已存在的编辑器能力 |

验证分为适当的 CPU/无头测试、外部 SDK 构建、图形运行和手工 VS 断点检查。模拟结果比较使用受控时间与输入的示例，不把所有引擎系统宣称为跨平台确定性模拟。
