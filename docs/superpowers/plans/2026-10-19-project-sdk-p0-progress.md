# 项目代码接通 P0：交付与取舍记录

P0 接通了外部 C++ 项目会话、编辑器 Play/Stop 和独立游戏。它还没有项目组件的属性面板、撤销、Prefab 或完整发布链路；这些仍属于 P1–P4。使用步骤见[项目代码开发](../../项目代码开发.md)。

基础实现阶段完整 Debug 回归为 23/23。独立审查发现的构建身份、旧代码发布、插件依赖、模板启动文件和宿主 DLL 安装问题已补充复现：定向检查由 0/6 转为 6/6；安装后的 SDK 游戏、同一 DLL 的 PIE 和真实编辑器入口检查也通过。提交后的最终全量结果随本地交付包的 `artifacts/ProjectSDK-P0/验收报告.md` 保存。

独立审查反馈了上述问题后因服务限额中断，未给出完整结论。已反馈的重要问题由实现者修复并验证，余下 C 接口、对象所有权、失败清理和装载路径由实现者自查；不能把这写成独立审查完全通过。

## 实施取舍

1. 在独立工作树实施，复用主目录原有但被忽略的旧测试源码及音频夹具。没有修改它们的原件；代价是干净克隆的旧测试仍有既存的文件跟踪问题。
2. SDK 构建规则放入独立 CMake 文件，保留旧引擎配置的可构建性。项目模块只承诺 Debug/Release；代价是额外两种旧配置的元数据仍需维护。
3. 清单优先保存每个配置自己的 SDK ID，并兼容旧全局字段。这样 Debug/Release 可共存；代价是多一个配置字段及兼容分支。
4. 把变化频繁的构建身份定义仅提供给实际使用它的源文件。报告的身份保持一致；代价是新增使用者必须显式取得这些定义。
5. 空 World 重置也通知监听器，让所有重置都更换外部世界身份。代价是监听器必须能安全处理重复清理通知。
6. Windows 游戏及验证入口使用宽字符参数转换为 UTF-8，宿主按配置安装。代价是入口改变需要实际命令行回归，本轮已覆盖。
7. 旧 DPI 测试补上真实启动场景，保留“显式项目/场景错误就报错”的产品行为。代价是该测试不再间接覆盖演示场景创建；这不是它的测试目的。
8. VS 工具两次无法定位文件选择控件后停止 UI 验证，没有宣称断点命中。没有独立干净 Windows VM；代价是这两项仍需手工/独立环境验收。
9. 项目身份跟踪隐式头文件、CMake 配置、用户缓存及目录结束时的目标设置；SDK 跟踪源码和 Git 引用。代价是部分无关输入也会触发保守重编译。构建设置应保存在 CMake，不能依赖手改生成工程。
10. 通用插件沿用原生依赖搜索行为，项目模块使用显式搜索；安装宿主时收集 CMake 声明的 DLL 依赖。代价是通用插件仍保留原有 PATH/当前目录搜索行为，最低 CMake 提升至 3.21。

## 尚待验收及后续工作

- 按开发文档在 VS 命中外部项目 Update 断点，并核对影子 DLL/PDB；自动检查只证明文件配对存在及代码执行。
- 在干净 Windows 环境检查发布运行依赖；本轮只验证本机及独立临时目录，不冒充干净机器验收。
- 低优先级兼容事项：内部宿主复制比当前结构更大的 HostAPI 时，仍保留调用者的尺寸标记；当前 Bridge 的表尺寸精确，扩展宿主表之前应收缩标记或复制完整数据。
- P1 类型/属性与数据保存，P2 通用编辑和资源引用，P3 构建调试体验，P4 Cook/项目代码和依赖打包，仍需按原规格继续实施。
